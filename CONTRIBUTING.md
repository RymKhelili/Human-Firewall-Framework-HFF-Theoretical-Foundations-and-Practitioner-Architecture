# Contributing

Thanks for your interest in the Human Firewall Framework (HFF). This is a living, research-grounded project, and contributions are welcome — especially ones that strengthen its evidentiary base or stress-test its practical claims.

## Ways to contribute

- **Point out relevant research** — If you know of a study, meta-analysis, or literature review (published or in preprint) that supports, complicates, or contradicts a claim in Part I, please open an issue with the citation and a short note on where it's relevant.
- **Adversarially test the framework** — Per Part II §3, every mechanism taught under the HFF should be able to withstand the question "how would an attacker route around this?" If you can think of a way a specific function or exercise design fails that test, open an issue describing it.
- **Suggest edits for clarity** — Both documents aim to state their claims precisely and cite their sources honestly. If something is unclear, overstated, or under-cited, a pull request or issue is welcome.
- **Report broken references** — If a citation looks wrong, incomplete, or unverifiable, flag it.

## What this project is not looking for

- Content that weakens the distinction between sourced literature claims and reasoned architecture (see Part II §5) — please keep that line visible in any edits.
- Unsourced claims presented as established research.

## How to submit changes

1. Fork the repository.
2. Create a branch for your change (`git checkout -b fix/citation-typo`).
3. Make your edit, keeping the existing tone and citation style consistent.
4. Open a pull request describing what changed and why.

## Code of conduct

Be respectful and constructive. This project deals with manipulation and deception as subject matter — disagreement about the research or the framework is expected and welcome; bad-faith argument is not.
